### 踩到的坑 / 设计取舍（详见 MEMORY.md §1c、§4b）

1. **`has_part` 的闭包方向与直觉相反**：`closure.ancestor` 恒等于边的 **dst**（I3）。
   has_part 边是「整体→部分」，dst 是部分 → **部分在 ancestor 侧**。
   `get_ancestors(脑,'has_part')` 返回的是「脑的组成部分」。已在 SQL §2.2 显式标注。
2. **跨库边源词不一定是名词**：照抄 ext 的 `e.pos='n'` 会让「吃」（v）那条边
   **静默消失**（cross_links 只出 2 行）。实测发现并修。
3. **`信号` 在通用库不存在**（grep schema+seed+ext 全无），但需求要求
   「通用库信号 → 医学库脑电图信号」。按 ext 的兜底先例补建（4101 段），
   并在文件里标注它是通用库词条，便于将来合并。
4. **前置依赖硬检查**：用「临时表 + 具名 CHECK 约束」把修复提示写进**约束名**，
   裸 schema 上加载会报
   `CHECK constraint failed: _prereq_missing_run_seed_general_v3_and_ext_first`。
   比 ext 的 `NOT EXISTS` 静默跳过更强 —— 医学树若挂在缺失的「抽象概念」上会成孤岛。
5. **未新增 `semantic_categories` 行**，医学节点只映射到已有粗类
   （抽象 4 / 实体 8 / 事件 9 / 性状 10），与 ext 的取舍一致。
