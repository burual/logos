**踩坑与方法论**
1. **`init_database` 自动发现 `seed_*.sql`**（`SEED_GLOB`，按文件名排序）→ 新种子文件
   无需注册即进入所有 e2e/解析器测试的库。副作用：`tests/test_e2e_cat_eats_fish.py`
   夹具的 2001/2002 与本文件新增段位撞车，`UNIQUE constraint failed: words.word_id`。

2. **字典序恰好给出正确依赖顺序**：`seed_general_v3.sql` < `seed_general_v3_ext.sql`
   （`.` U+002E < `_` U+005F）。扩名必须落在基础种子之后。
3. **`INSERT ... SELECT ... ON CONFLICT` 必须带 WHERE**（哪怕 `WHERE 1`），否则 SQLite
   把它解析成 `SELECT ... ON` 连接语法而报错 —— seed §9 已记录，本文件沿用。
4. `relations` 的 `src_id/dst_id` **没有外键**，端点由触发器 `tr_relations_validate_ai`
   校验。因此外键诊断器要特判 `relations`，从字面量反推悬空 sense/node id。
5. 断言编号要"守住数量"：需求给定 12 项（77 总数），额外检查（has_property / cross_links /
   量词 / 新 relation_constraints）以 `[ok]` 非计数形式透明报告，不污染 77 这个数字。
